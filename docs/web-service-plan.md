# Web-сервис приставки: план реализации

Черновик 2026-11-25. Цель: обычный пользователь ставит игры, читает журналы, забирает
отчёты и обновляет систему из браузера на компьютере, подключённом кабелем; тот, кто
готов возиться, настраивает любую игру (управление, экран, тонкие ключи) в «Мастерской»
и получает готовый рецепт для репозитория. GO Ultra; GO Advance позже, если понадобится. Компьютер пользователя: Windows или
Linux, равноправно (см. «Решения»).

## Ночь 2026-11-25 → 26 (решения пользователя)

Все этапы подряд, включая Мастерскую; всё остаётся в ветке `web` (SDK и bare_app), в
master не сливать, не пушить; режим сервера решить по замеру памяти. На OGU1
подключены Wi-Fi и UART (/dev/ttyUSB0). Пользователь вернётся 07:30. Обновление из
браузера проверять установкой в запасной слот без перезагрузки в него.

## Что уже есть и на что опираемся

- Сеть по кабелю: S42usbnet, NCM, приставка `<net>.2` (192.168.7.2, ogu2 192.168.8.2),
  компьютер получает `<net>.1` по DHCP. Накопитель «USB-диск» добавляется в тот же
  гаджет, сеть при этом не рвётся.
- Python 3.14 в rootfs целиком (19 МБ): http.server, json, html, zipfile, Pillow.
- Команды с построчным протоколом для UI: `game-install scan|install|remove|prepare-card`
  (step/progress/skip/done/fail), `system-update FILE` (step/progress/done), `bare-report
  [GAME]` (путь файла), `ab-state`.
- FIFO bare_app `/tmp/bare_app.ctl` (view_ctl.c): `launch NAME`, `options NAME`,
  `quit-game`, `back`, `open SCREEN`, `press|release BTN`. Скриншот: SIGUSR1 → PPM в
  `$BARE_APP_SHOT` (view.c, CONFIG_SNAPSHOT). scripts/ogu-ctl.py делает это с ПК.
- wine.ini игры читают двое: bare_app (src/games/wine.c, имя, подсказка, обложка,
  опции) и bare_app_wine (ports/wine/bare_app_wine.c, всё остальное). Правки игрока с
  экрана «Управление» лежат отдельно, в bare_app.conf `controls.<game>` (перестановка
  кнопок), опции в `options.<game>`.
- Рецепты прошивки в /usr/share/game-recipes (post-build.sh копирует games/ + manifest).

## Решения

- Один сервис `bare-web` (/usr/sbin/bare-web, Python, ThreadingHTTPServer), порт 80,
  статика в /usr/share/bare-web (HTML/JS/CSS без CDN: у приставки нет интернета).
  JSON API под /api, долгие операции = задания с прогрессом по SSE (text/event-stream).
- Запуск: init-скрипт S43web после сети. Этап 1 измеряет RSS; если больше ~15 МБ,
  переходим на запуск по состоянию UDC (`configured`) и остановку при отключении кабеля.
- Доступ без пароля только с usb0. Доступ по wlan0 отдельным этапом с PIN на экране.
- Загрузка файлов: PUT /api/upload/<место>/<имя> с телом-файлом (fetch(body=File)),
  без multipart: поток в `<имя>.part`, затем rename. Папки: webkitdirectory, до 4
  запросов параллельно; для папок из тысяч файлов руководство оставляет USB-диск.
- Карта /games монтирована только для чтения: писать через remount rw/ro как делают
  bare-report и game-install (`card_rw`). Один файл-замок /run/game-install.lock на
  установку, его берёт сам game-install, чтобы экран приставки и сайт не мешали друг
  другу.
- Компьютер с Windows и с Linux (и macOS) равноправны: на стороне ПК только браузер
  (Chrome, Edge, Firefox; выбор папки через webkitdirectory есть во всех), сеть по
  кабелю без драйверов (NCM встроен в Windows 11, macOS, Linux; Windows 10 см. этап 7)
  и exFAT-карта в режиме «USB-диск». Все файловые потоки (установщики, redist,
  обновления, отчёты, резервные копии) имеют второй путь через папки на карте, чтобы
  без сети тоже работало. Скрипты для ПК (recipe-import.py) пишутся переносимо:
  pathlib, без символических ссылок и прав доступа, проверяются на Windows.
- Список игр и их данных даёт сам bare_app: при каждом сканировании он пишет
  `/run/bare_app/games.json` (папка, имя, движок, каталоги данных по game_def.storage:
  `saves` wine.ini, /data/wine/games/<папка>, каталоги VCMI и т. д.). Сайт и резервные
  копии опираются на этот файл, а не на свою копию правил.
- Правки Мастерской хранятся не в wine.ini игры, а в `/games/recipes/<папка>/wine.ini`
  (слой поверх рецепта), чтобы переустановка игры их не стирала и их можно было
  перенести на другую приставку.

## Организация работы: роли и модели

Пользователь решил 2026-11-25: координация и приёмка на Fable, остальная работа на
более дешёвых моделях через агентов (определения в ~/.claude/agents/).

| Роль | Агент | Модель | Что делает |
|---|---|---|---|
| координатор | сессия | Fable | читает план, пишет исполнителю дословную задачу этапа с критериями приёмки, принимает отчёт, сам проверяет ключевые утверждения (сборка, тест, приставка), обновляет план и память |
| исполнитель | builder | Opus | код, тесты на копиях, прогон на OGU1, коммиты в ветку web, отчёт с подтверждениями |
| тестировщик | reviewer | Opus | независимая проверка этапа по дословной задаче и диффу, VERDICT PASS/FAIL |
| писатель | writer | Sonnet | главы руководства, памятки на карте, тексты экранов по готовому коду |

Правила координатора:
- Этап запускается агентом builder; задание содержит: номер и текст этапа из плана,
  критерии приёмки, ветки, что лежит на диске для теста (установщик, .upd, резервная
  копия), чего не трогать (OGU2, master, push).
- Один builder на этап; если этап делится на независимые куски без общих файлов, можно
  два параллельно, но на приставку ходит только один.
- Приёмка: отчёт builder → reviewer с той же задачей и диапазоном коммитов → при PASS
  координатор сам повторяет одну-две ключевые проверки (не доверяя обоим) → слияние в
  master без push → запись в план и память. FAIL только по тестам при верном коде
  пользователь обычно пропускает (см. память feedback-skip-test-only).
- Документацию этапа пишет writer после PASS, по отчёту builder и коду; снимки экранов
  делает координатор через ogu-ctl.py.
- Мастерскую (этапы 4–5) делать днём с пользователем: builder выдаёт рабочий вариант,
  пользователь пробует, координатор формулирует правки.

Модель по этапам: 1, 2, 6, 7 — builder (Opus); 3 и правки в C bare_app (games.json,
файл состояния, FIFO reload, перенос перестановки кнопок) — builder (Opus) только с
написанной до кода матрицей сценариев в задании и обязательным reviewer; 4–5 —
builder (Opus) с пользователем; 8 — builder (Opus) в свободный вечер; документация —
writer (Sonnet).

## Правила работы (из прошлых сессий)

Ветка `web` в SDK и bare_app; тест после каждого шага; на реальной приставке только OGU1
(192.168.7.2), перед первым тестом с картой и /data резервная копия; тесты только на

в конце независимый тестировщик (reviewer), слияние в master без push.

## Этап 1. База: установка, журналы, отчёты, обновление (1–1,5 дня)

1.1 Каркас. `board/common/.../usr/sbin/bare-web`, `/usr/share/bare-web/{index.html,

    карте и в /data, батарея, имя unit. Страница с меню: Установка, Игры, Журналы,

1.3 Сканирование и установка. `/api/install/scan` → JSON по строкам game-install;
    `/api/install/run {path, replace, exe, title}` → задание, SSE со step/progress,
    `done`/`fail` с теми же русскими формулировками, что в ctl_install.c (таблица
    кодов fail дублируется в Python; отметить в обоих файлах). Выбор программы для
    неизвестной игры (строка `exe`). Удаление записи (`remove`). Замок (см. выше):
    game-install получает `flock` на /run/game-install.lock, второй вызов → fail busy.
    Проверка: установка из браузера даёт тот же результат, что с экрана «+» (md5 папки
    игры совпадают), плитка появляется на главном экране без перезапуска bare_app.
1.4 Файлы Windows. Страница показывает строки `need` для каждой записи и зону
    загрузки в redist; ссылка на страницу Microsoft с DirectX June 2010.
1.5 Игры и журналы. `/api/games`: папки /games с wine.ini или game.ini + встроенные

    отдаёт 1..3.log целиком; страница с просмотром и скачиванием.
1.6 Отчёты. `/api/report?game=` запускает bare-report и отдаёт файл; список
    /games/reports и /data/reports со скачиванием и удалением.
1.7 Обновление. Загрузка .upd, `system-update --info`, `/api/update/run` → задание с
    прогрессом, `done` → кнопка «Перезагрузить» (`/api/reboot`), «Перейти на запасную»

1.8 Документация: глава docs/user-guide/chapters/40-web.md («Приставка в браузере»),

1.9 Тесты на ПК: scripts/test-bare-web.py (unittest, сервер в процессе, каталоги через
    GAME_INSTALL_* и переменные bare-web), на копиях данных.

(S43web при загрузке); запуск по кабелю не делался — решает координатор.

fail-кодов продублирована в bare_web.py (тексты живут в i18n.c, не в ctl_install.c;
общий ini не делался), пометки в i18n.c, ctl_install.c и bare_web.py; папки
целиком не загружаются (имя без `/`, страница отсылает к USB-диску); обрыв загрузки
удаляет .part (строже плана), висящее соединение рвётся по таймауту 120 с; bare_app на
OGU1 не пересобран: старый показывает `fail busy` словами game-install по-английски.
Известное ограничение: если карту сделал rw game-install и в это время идёт загрузка
сайта, его remount ro не пройдёт (busy) и карта останется rw до следующей записи
bare-web/game-install.

## Этап 2. Сохранения: резервная копия и перенос на другую приставку (1 день)

2.1 Что входит в копию игры: каталоги данных из games.json (сохранения, настройки игры,
    файлы `writable`), записи `controls.<game>` и `options.<game>` из bare_app.conf,
    слой рецепта /games/recipes/<папка> (этап 3). Не входит: папка игры на карте
    (это установка, не данные), настройки Windows-игр в реестре общего префикса
    (редкость; `reg` рецепта накатывается при каждом старте и так).
2.2 Формат: zip `saves-<папка>-<дата>.zip` с `manifest.json` (приставка, дата, версия
    системы, игра, список каталогов с размерами и md5) и каталогами относительно
    /data. Копия всей приставки: `saves-all-<дата>.zip` = все игры + bare_app.conf без
    секций сетей (пароли Wi-Fi и ключи Bluetooth не берём) + /games/recipes.
2.3 bare-backup (sh или часть game-install): `backup GAME|all [DIR]`, `restore ZIP

## Риски

- Память: Python-сервер ~10–15 МБ при играх у предела памяти → запуск по кабелю.
- Одновременные записи на карту сайтом и приставкой → замок game-install и remount по
  счётчику (bare-report уже так делает).
- Карту вынули или включили «USB-диск» во время загрузки → сервер отвечает 503 и
  страница объясняет; .part не считается записью.
- Восстановление поверх живых данных: игра не должна идти (сайт отказывает, если
  games.json/state показывает её запущенной); каталоги уводятся в .bak до распаковки.
- Windows 10 без NCM: см. этап 7; Windows 11 проверена 2026-11-25, 10 нет.
- Дублирование русских текстов fail-кодов в C и Python → вынести таблицу в
  /usr/share/bare_app/errors-install.ini, читаемую обоими (можно в этапе 1.3 сразу).
