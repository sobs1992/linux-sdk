# Аудит игр GO Ultra: стабильность и управление (2026-11-20)

Проверка всех игр SDK на ODROID-GO Ultra (экземпляр 1, `192.168.7.2`, ядро #51,
GPU 666 МГц; репозиторий на начало аудита: SDK `ef78e14`, bare_app `acab146`;
20–21 ноября 2026) глазами игрового тестировщика:
падает ли игра, переживает ли сворачивание, сон и гибернацию, и удобно ли в неё
играть кнопками консоли. Для каждой игры — текущее управление, что с ним не так и
что предлагается изменить; отдельно — где кнопок консоли не хватает.

Документ написан так, чтобы по нему можно было работать без этой сессии:

- **Человеку** — сводная таблица (раздел 4), затем раздел своей игры.
- **Другой сессии Claude** — у каждой рекомендации есть идентификатор (`DOOM3-1`),
  файл, что именно поменять и как проверить. Рекомендации независимы, если не
  сказано иначе. Перед правкой прочитать раздел 2 (как устроены раскладки), после
  правки — обновить `games/README.md` «Раскладка», подсказку игры (`hint`,
  `hint.ru`) и `[labels]`, иначе экран «Управление» (X на плитке) будет врать.

Раздел 6.20 (The Book of Unwritten Tales) добавлен 2026-11-21: игра портирована в этот
день и проверена на экземпляре 2 (`192.168.8.2`), а не на OGU1.

Пометки: **[проверено]** — видно на устройстве в этом аудите; **[по коду]** —
выведено из исходников и конфигов, на устройстве не проверялось; **[руками]** —
нужна проверка человеком (звук, ощущение стиков, физические кнопки) — собрано в
разделе 7.

## 1. Консоль: органы управления

Из device tree (`meson-g12b-odroid-go-ultra.dts`) и bare_app:

| Орган | Есть | Замечания |
|---|---|---|
| Крестовина | да | цифровая, 4 направления |
| A B X Y | да | ромб, подписи как у Nintendo/Xbox-подобных пультов: A справа, B снизу, X сверху, Y слева (коды `BTN_EAST/SOUTH/NORTH/WEST`) |
| L1 R1 | да | цифровые |
| L2 R2 | да | **цифровые** (кнопки, не курки): ни плавного газа, ни плавного тормоза |
| F1…F6 | да | ряд из шести кнопок под экраном; играм доступны **F1–F4** |
| Громкость + / − | да | всегда у bare_app |
| Питание | да | коротко — сон, 2 с — выключение; всегда у bare_app |
| Левый и правый стик | да | аналоговые (`adc-joystick`, опрос 10 мс) |
| Нажатие стиков (L3/R3) | **нет** | в DTS нет `BTN_THUMBL/THUMBR` |
| Отдельные Start / Select | **нет** | их роль играют F1 (Start) и F4 (Back/Select) — по договорённости SDK |
| Вибрация, тачскрин | нет | |
| Гироскоп | только внешний | модуль ICM-20948 по USB (pico), см. память `motion-sensor-gyro` |

Кнопки опрашиваются драйвером `gpio-keys-polled` раз в 16 мс; для человека это
незаметно.

**Что bare_app забирает себе (играм недоступно):** F5 коротко — свернуть (по
отпусканию), F5 0,6 с — монитор системы, F6 2 с — выход из игры, громкость,
питание; в играх с `volume = triggers` (HotA) — ещё L2/R2.

**Итого у игры:** 16 цифровых кнопок (крестовина 4, ABXY 4, L1 R1 L2 R2, F1–F4) и
два стика. Пульт Xbox 360 даёт те же 16 кнопок, но иначе: у него есть L3/R3 и
аналоговые курки, нет F-ряда. Поэтому всё, что на консолях висит на **нажатии
стика** (бег/спринт, присесть, приближение, «осмотреться»), на GO Ultra нужно куда-то
переносить — это главный источник «нехватки кнопок» ниже. F-ряд под экраном
неудобен для действий в бою (большой палец уходит со стика/кнопок): на F1–F4 стоит
класть только меню, сохранение и редкие действия.

## 3. Методика

**Что проверялось у каждой игры** (матрица; в разделе игры — что прошло):

| Шаг | Как |
|---|---|
| запуск с плитки | `launch <id>` в `/tmp/bare_app.ctl`, снимок экрана |
| меню игры | F1, навигация крестовиной/стиком, A/B |
| начало игры / загрузка уровня | новая игра или загрузка сохранения |
| игра 10–15 мин | скрипт: ходьба, обзор, огонь, действие, прыжок, присед, смена оружия (шутеры); клики и прокрутка (мышиные игры) |
| сохранение / загрузка | F3/F2 или меню игры |
| свернуть / развернуть | F5, снимок плитки с паузой, F5 |
| выход | F6 2 с, затем код выхода в журнале bare_app |
| перезапуск | снова с плитки, загрузка сохранения |
| нагрузка | каждые 5 с: процессы игры, RSS, CPU, свободная память, swap, температура, частота GPU, ток батареи, состояние звука (`pcm hw_ptr`), в конце — новые строки dmesg |
| сон / гибернация | **не прогонялись по всем играм** (см. ниже) |

**Сон и гибернация.** Сон (s2idle) проверен на Героях III: 5 часов сна посреди
игры, после пробуждения игра, звук и картинка на месте. Тест сна по всем играм и
тест гибернации отложены: при первом прогоне будильник был поставлен на
`rtc0` (`meson-vrtc`), который s2idle не будит, и плата спала до нажатия
питания человеком. Будильник для s2idle — только `rtc1`/`rtc2` (`rk808-rtc`).
Гибернация с игрой в памяти и выключением питания требует человека — в чек-листе
(раздел 7).

**Инструменты (временные, на плате только в `/tmp`, в rootfs ничего не
ставилось):**

- кнопки консоли — `press`/`release` в `/tmp/bare_app.ctl` (как
  `scripts/ogu-ctl.py`), стики — `/tmp/ogu-hold` (события `EV_ABS` в
  `adc-joystick`);
- мышь и клавиатура для меню, которые пультом не пройти, — свой модуль
  `uinput.ko` (собран отдельно против ядра #51) и программа `vinput`
  (виртуальная USB-клавиатура и мышь; bare_app видит её как обычную USB-мышь).
  **Рекомендация TOOLS-1:** включить `CONFIG_INPUT_UINPUT=m` в конфиг ядра GO
  Ultra: автоматические тесты игр смогут вводить мышь/клавиатуру без сборки
  модуля «на стороне»;
- снимки экрана — `scripts/ogu-ctl.py shot:`;
- журнал bare_app: в конце игры строка `N frames shown, X over 50 ms, Y over 100
  ms, worst Z ms` (см. BAREAPP-1 о её неточностях).

## 5. Сквозные рекомендации (касаются многих игр)

- **X-1. Сохранение с пульта — не больше 2–3 нажатий, без ввода текста.** В Doom
  сохраниться с пульта нельзя совсем (DOOM-1). В Fallout путь длинный, и в описание
  попадает случайная буква (FALLOUT-1). Правило для новых игр: F3 — быстрое
  сохранение, F2 — быстрая загрузка, там где они у игры есть (Fallout F6/F7,
  Pirates! Shift+S/Shift+L, Half-Life, DOOM 3, RTCW, Serious Sam — уже); полный
  экран записи — через меню F1; если игра просит имя — подставлять его
  (Doom — по уровню, HotA уже так делает).
- **X-2. «Продолжить» сразу после запуска.** F2 в главном меню Half-Life и Serious Sam
  ничего не делает (быстрая загрузка — только в игре). На консолях первое, что
  видит игрок, — «Продолжить». См. HL-3, SSAM-2.
- **X-3. Бег и другие действия L3/R3 — от отклонения стика.** У консоли нет нажатия
  стиков. Порт Doom уже бежит при отклонении стика больше 0,8 (`STICK_RUN`).
  Сделать так же в DOOM 3 (DOOM3-1: бега нет совсем) и RTCW (RTCW-4: бег на Y мешает
  обзору). Где L3/R3 нужны как кнопки (The Bard's Tale) — F3/F4 =
  `pad_ls`/`pad_rs`, как сейчас.
- **X-4. Крестовина в списках меню.** В Героях (VCMI и HotA) и RTCW крестовина не
  выбирает строку в списках сохранений (HOMM3-1, HOTA-1, RTCW-1), в Syberia B не
  закрывает экран загрузки (SYB-1), в Half-Life у меню в игре нет фокуса (HL-2).
  Проверочный вопрос для каждой новой игры: «можно ли загрузить сохранение, не
  трогая стик-курсор?».
- **X-5. Незаданные кнопки Windows-игр шлют значения по умолчанию** (Shift, Ctrl,
  PgUp/PgDn, F2–F4 — `src/games/wine_defaults.h`). Игры их обычно не используют,
  но Shift/Ctrl меняют смысл клика, а экран «Управление» показывает эти кнопки
  без подписи. Предложение: в `wine.ini` каждой игры явно `none` для неиспользуемых
  (NFH-1, SYB-3, MI-4), или в bare_app: кнопка без `[labels]` и без `[keys]`
  получает `none` — одно правило вместо правок в каждой игре (решить владельцу;
  второе меняет поведение старых `wine.ini`, проверить все игры).
- **X-6. Значки кнопок в играх с пультом.** Пульт Wine (патч 0026) называется
  «GO Ultra gamepad»; The Bard's Tale из-за этого (вероятно) рисует значки PS3, не
  совпадающие с подписями консоли (BARD-1). Переименовать в `Controller (XBOX 360
  For Windows)` и проверить The Bard's Tale, NFSU, Monkey Island.
- **X-7. B (Esc) в главном меню может мгновенно закрыть игру.** Fallout (FALLOUT-2):
  Esc в главном меню — «Выход» без вопроса. Выход из игры на консоли — F6 (2 с);
  подсказки на старте не должны учить «B — пропуск роликов» в таких играх.
- **X-8. Подсказки и документация отстают от раскладок.** Doom («B бег»),
  Half-Life (нет Y/F4), Shade (README про F2–F4 и Y/L1 устарел — см. SHADE),
  `apps/bare_app/README.md` про F1 у Героев (HOMM3-2), Syberia (B — инвентарь, а не
  «меню»). Правило: менять `[keys]`, `[labels]`, `hint` и `games/README.md` одним
  коммитом (раздел 2).
- **BAREAPP-1 (мелочь) [по коду, проверено в журналах]. Статистика кадров в журнале
  считает паузы рывками.** `frame_shown()` (`src/gui/view/core/view_video.c`)
  меряет интервал от прошлого кадра без учёта свёрнутой игры, сна и неподвижной
  картинки Wine (кадры не шлются): после 5 часов сна — `worst 4294967 ms` (интервал
  упёрся в `UINT32_MAX` мкс), после свёрнутой HotA — 1642 «дольше 100 мс» из 7062. В
  строке игр из `game.ini` вместо имени — `native:`. *Что сделать:* сбрасывать
  `last_us` при паузе/продолжении игры и после сна (`power: woken up`); паузы Wine
  длиннее `FRAMETIMES_IDLE_US` не считать (как в `frametimes_summarize`); в строку
  писать id игры. *Проверка:* свернуть игру на 30 с — в строке нет интервала 30 с.
- **TOOLS-2 (для разработки).** USB-сеть до OGU1 несколько раз пропадала на 10–120 с
  (`No route to host`), плата при этом работала (игра шла, uptime не сбрасывался).
  Мешает автотестам и `ogu-ctl.py`. USB при этом не отключался (`journalctl -k`
  на ПК: событий для порта OGU1 нет; переподключался только OGU2 на другом порту, и
  не в эти моменты) — сбой на уровне IP/ARP. Проверить: `ip neigh` на ПК во время
  сбоя, `dmesg` платы (`g_ncm`/`usb_f_ncm`), не меняет ли NetworkManager что-то на
  `enx024f47550001` (DHCP-сервер ПК для 192.168.7.x).

## 6. Игры

Порядок: свои движки, затем игры под Wine. В каждом разделе: как управляют в
похожих играх на консолях, текущая раскладка, что проверено, рекомендации, нехватка кнопок.

### 6.1 Doom (`doom`) — шутер, 1993

**Как на других консолях.** Doom (1993) для Switch/Xbox/PS (порт 2019): огонь — правый

## 7. Чек-лист ручных проверок (человеком, на OGU1 или OGU2)

Что автоматикой не проверить: звук, ощущение стиков и кнопок, а также сон и
гибернация с отключением питания. Отмечать `[x]` и писать замечание рядом.

**Сон и гибернация (по 1–2 игры каждого движка: Doom, VCMI, Xash, DOOM 3, Wine-игра, Serious Sam)**

- [ ] Игра идёт → короткое нажатие питания → экран гаснет → через 1–2 мин снова
      нажатие → игра продолжается, звук есть (автотест: только Герои III, 5 часов
      сна — без потерь).
- [ ] То же с включённой гибернацией (Настройки → Система → Гибернация): игра в
      памяти, плата выключается, включение — игра на месте, звук есть (после
      ядра #51: патчи 0033/0034).
- [ ] Гибернация с Wine-игрой (самая большая память: The Book of Unwritten Tales
      до ~760 МБ в главе 2, Fallout ~470 МБ, Monkey Island ~380 МБ).

**Звук**

- [ ] В каждой игре: музыка и эффекты, нет треска и «песка» (в журналах HotA и PoP были
      `underrun` ALSA при старте — проверить на слух).
- [ ] Громкость кнопками ± во время игры; в HotA — L2/R2 (пока HOTA-2 не сделано).
- [ ] После F5 (свернуть) и обратно — звук возвращается.

**Стики и кнопки**

- [ ] Half-Life, RTCW, DOOM 3, Serious Sam: обзор правым стиком — нет дрейфа, скорость
      поворота удобна, мёртвая зона не мешает точному прицелу.
