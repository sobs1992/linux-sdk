# Предисловие

Образ собрался, записан на карту, плата загрузилась до `login:`. Значит ли это, что
всё работает? Нет: экран может быть повёрнут не туда, звук молчать, а модуль
Ethernet — не загрузиться. Эта книга — набор **процедур проверки**: что проверить на
каждой плате, какой командой и что считать результатом.

## Как устроена книга

- **Глава 1** — общая методика: подготовка, запись, журнал UART, стадии загрузки,
  автоматический скрипт `board-check.sh` и протокол испытаний.
- **Глава 2** — проверки Linux, одинаковые для всех плат.
- **Главы 3–6** — процедуры для каждой платы: OGA, BBB, RPi 1, RPi 4/400.
- **Глава 7** — что делать, если проверка не прошла.
- **Приложения** — шаблон протокола и листинг скрипта.

## Что нужно

| Что | Зачем |
|---|---|
| USB-UART адаптер на 3,3 В | журнал загрузки, консоль |
| Картридер и запасная SD-карта | прошивка, восстановление |
| Сетевой кабель, роутер с DHCP | BBB, RPi |
| USB-флешка | проверка USB-хоста |
| Наушники / динамик, HDMI-монитор | звук, видео |
| Светодиод + резистор 330–1000 Ом, перемычки | GPIO, UART-петля |
| USB-клавиатура (для RPi 4, BBB с HDMI) | консоль на экране |

## Достоверность

Каждая проверка помечена:

- **проверено на железе** — так было на настоящей плате при создании SDK;
- **ожидаемо** — результат выведен из исходников, конфигурации ядра и DTS, но на
  железе ещё не наблюдался.

На момент написания на железе проверялась только ODROID-GO Advance Black Edition:
загрузка, экран с поворотом, кнопки и стик. Всё остальное — ожидаемые результаты,
и протокол испытаний (приложение A) нужен, чтобы превратить их в проверенные.

!!! note "Как читать результаты"
    Если результат проверки отличается от описанного, это не обязательно ошибка
    платы: имена устройств, номера и порядок могут меняться между версиями ядра.
    Ошибка — когда **функция** не работает (нет звука, кнопка не даёт событий).
