6. Нюансы и подводные камни

Всё ниже — не теория, а то, на что уже наступали. Сгруппировано по месту.

Сборка

  • Один тяжёлый компонент за раз. Машина с 14 ГБ: make без -j сверху, VCMI в 4 потока по ~1 ГБ (VCMI_JOBS). Ad-hoc скрипты ограничивать (ulimit/MemoryMax): OOM-kill внутри VS Code закрывает VS Code.
  • -dirclean, не -rebuild после правки патча пакета: Buildroot накладывает патчи только при распаковке. rebuild — для проверки правки прямо в output/<fw>/buildroot/build/<pkg>-<версия>, в образ попадает патч.
  • SDL2 не пересобирается сам, когда меняется bare-app.SDL или его патчи: make rootfs-make BR=sdl2-dirclean, потом make rootfs.
  • Каждая правка патча ядра — копия дерева заново (~1,8 ГБ, часы на пересборку затронутых файлов). Патчи ядра и U-Boot не правят «ради красоты».
  • .config компонента пересоздаётся, когда меняется defconfig или фрагмент; правки из menuconfig живут до этого момента — *-savedefconfig или во фрагмент. scripts/kconfig-check.sh скажет, какие строки фрагмента не попали в .config.
  • make <fw>_defconfig — отдельной командой. make oga_defconfig all в одной строке — ошибка (конфиг ещё не загружен).
  • make flash пишет образ выбранной прошивки. make info перед записью.
  • make linux стирает linux-install/ и ставит модули заново.
  • Выключенный пакет остаётся в target/ у чистого Buildroot. SDK это чинит (apps-config.sh dropped), но пакет, пересобранный вручную (X-rebuild), до следующего configure имеет пустой список файлов, и purge его не увидит.
  • Buildroot target/ помнит выключенные пакеты иначе: после реконфигурации проверяйте ls output/<fw>/buildroot/target/usr/share/bare_app/games/.
  • Патчи Mesa (mesa-panfrost-dirclean): зависящие от неё пакеты пересобирать не нужно.
  • Нумерация патчей сплошная по каталогу; при слиянии веток с патчами (gothic 0025–0027 поверх pop 0025) номера приходится переставлять.

Диски и карта игр

  • /games только для чтения. Всегда. Игра, которая пишет в свой каталог, получит ошибку — Wine-игре нужен writable, SDL-игре — {data}. Проверять финально нужно именно так: карта в rw скрыла запись MSSSOFT.M3D, из-за которой Gothic не запускался у пользователя.
  • exFAT и FAT не знают регистра. DOOM3 и doom3 — один каталог; Wine ищет имена через stat() (патчи 0023/0024), иначе каждый открываемый файл стоил бы чтения каталога.
  • Кластер 32 КиБ при форматировании exFAT: по умолчанию 128, мелких файлов тысячи.
  • FAT32 — файлы до 4 ГБ. Ресурсы DOOM 3 BFG больше.
  • Карта подключается только при загрузке. Вставили позже — перезагрузка.
  • Карта с extlinux.conf — загрузочная: U-Boot загрузит систему с неё, и к eMMC она уже не добавится. Карта игр не должна нести файлы загрузки.
  • Запись образа стирает /data и /games на том диске (у games-image.py без --card). Сохранения снимать заранее: ssh root@… 'tar -cf - -C /data .' > data.tar.
  • Старая разметка (p4 на eMMC GO Ultra). Пока p4 есть, p3 не растёт. Удалять: games-mount stop; dd … p4 count=4; sfdisk --delete … 4; reboot.
  • USB-диск ~11 МБ/с, картридер быстрее. «Выключить» в GNOME убивает и сеть.
  • Ключ хоста dropbear меняется с каждым образом — ogu-ctl.py его не проверяет.

Wine-игры

  • Первый запуск после пересборки Wine падает один раз и может сбросить настройки игры (prefs). Запустить ещё раз.
  • Один префикс на все игры (/data/wine/prefix): шрифты, реестр, Documents общие. Строки reg в wine.ini ставятся при каждом старте (0,1–0,8 с), так что они и переживают пересоздание префикса.
  • profile копирует только то, чего ещё нет: правки пользователя не затираются. Файл с последним сохранением (prefs.prop Telltale) в overlay/profile класть нельзя — он назовёт чужое сохранение.
  • writable — только настоящие записи. Остальное — ссылки на /games; запись глубже (Sbz1/Save) делает родителей настоящими каталогами копии.
  • DirectInput-мышь. Wine держит курсор на месте, и каждая присланная позиция становится сдвигом: курсор «ползёт». mouse = relative.
  • Игра открывает файлы на запись, хотя не пишет (*.lod у Героев): патч Wine 0013 отдаёт read-only на ro-ФС без ошибки, копия не нужна.
  • scale = fill допустим только когда ширина 1:1 (854×600 → 854×480), иначе текст плывёт.
  • Никогда не уменьшать буфер самой игры (Neighbours from Hell): heap corruption. Перекладывать интерфейс, не экран.
  • Тёмные игры — gamma = 1.6 (Templar), не трогать настройки игры.
  • Мелкий текст — WINE_FONT_SCALE=1.25 + FREETYPE_PROPERTIES=truetype:interpreter-version=35 (v35 — хинтинг как в Windows, без него «c» слипается с соседом). Больше 1.25 — строки с фиксированным шагом налезают.
  • D3DX, OpenAL, шрифты из Windows — не в git, в lab/redist/.
  • NoMultisample=1 (Wine 0021) — сглаживание выключено: 19 → 39 fps у Monkey Island.
  • Launcher'ы GOG (gpp.exe, Launcher.exe) под Wine не работают — запускать сам exe (PoP: свой poplaunch.exe держит мьютекс, которого ждёт POP.EXE).
  • WINE_FAST_MUTEX только для игр, ждущих мьютексы WaitForSingle/MultipleObjects.
  • HeapMaps=2 роняет Pirates! — HeapMaps=1.
  • Рендер OpenGL старых игр (RndrGL у Templar) написан под расширения NVIDIA и падает в Mesa: оставлять Direct3D.
  • Монитор зависимости: CS-поток WineD3D на 100 % ядра — обычный потолок (PoP ~30 fps).

SDL2-игры

  • Не ставить SDL_VIDEODRIVER в [env]: драйвер bareapp выбирается сам; чужой даст чёрный экран и вечную «Загрузку…».
  • Игра не видит контроллер — читает /dev/input сама или знает только клавиатуру: keys.
  • Медленно на OGA — SDL_RENDER_DRIVER = software: A35 читает кадры GPU дольше, чем рисует.
  • vid_restart (смена режима) в движках Quake-семейства: драйвер брал функции GL из выгруженной библиотеки (SDL 0005).
  • Настольного OpenGL нет — GLES 2/3 и compat-контекст 3.1 через Mesa.
  • Mesa 25.0 pan_cast_and_pack ломала DOOM 3 (DATA_INVALID, падение preload): Mesa 0004. Утечки Bink и файлов ресурсов — engine 0018.

Игры с движком

  • Имя игры = каталог данных = ключ настроек. Переименовали — потеряли сохранения в меню и порядок плиток.
  • GAME_FRAME_SAME: движок, который не шлёт «кадр тот же», выглядит как зависший (монитор пишет «still»), а его простой не отличить от фриза.
  • VCMI под bare_app включает все моды из Mods (патч 0006): выключить мод — удалить каталог. Загрузка с HotA ~10 с.
  • Языки: язык игры = язык bare_app, действует со следующего запуска; тексты карт остаются, какими записаны.
  • Half-Life на OGA — программный рендер; выбор в меню игры хранится в video.cfg и переживает всё.

Плата

  • Reboot на GO Advance зависал — PMIC RK817 (ядро 0002); на GO Ultra U-Boot не видел SD после тёплой перезагрузки — DEV_OFF_RST RK818 (ядро 0017) + SD 50 МГц (U-Boot 0002). Когда сомневаетесь — poweroff, не reboot.
  • Никогда не трогать регистры PMIC живьём и не ставить governor performance обоим кластерам (плата повисала).
  • Не выгружать axg-sound-card.
  • Не печатать в UART, пока U-Boot ждёт (BOOTDELAY=0): остановить его — держать Enter с самого включения.
  • Bit-42 чтения под нагрузкой GPU на GO Ultra: ошибка аппаратная (кэш врёт, DRAM права); частота 666 МГц в ядре 0025 даёт 0 ошибок на стенде, 800 — ошибки и панику DOOM 3. Стенд — круглая кнопка «Стресс-тест» в меню.
  • Гибернация и GPU-буферы: без патчей 0028/0029 DOOM 3 не помещался в образ, а первое задание GPU после пробуждения падало (SError).
  • Батарея после сброса PMIC переоценивалась по OCV («86 %») — ядро 0031.
  • Часы RK817 отстают на 14 % — время берётся из RK818 (rtc-clock).
  • Wi-Fi дома: точка в состоянии CSA не даёт mac80211 аутентификацию (OGA).
  • CP2102 не читает 1,5 Мбод заводского miniloader OGA — это нормально, U-Boot уже на 115200.
  • Hardkernel-напряжения: vcc_lcd 3,0 В, при 3,3 В полосы и тусклая картинка.

Процесс работы

  • Сначала модель и инварианты, потом правки: матрица сценариев через настоящую точку входа и мутация каждого исправления. Локальные латки стоили шесть раундов ревью.
  • Проверять на обеих платах, если правка в общем коде (display_drm, SDL-драйвер).
  • Снимки и журналы в logs/, бэкапы eMMC/FIP//data — в lab/backups/<плата>/ перед любой записью загрузчика.
  • Карта игр и /data — пользовательские: games-image.py без --delete, сохранения не трогать без просьбы.
